# Domain docs

This repo uses a single-context layout. The glossary lives at `GLOSSARY.md`, and architecture decision records (ADRs) live in `docs/adr/`.

Before exploring the codebase, read the root glossary and any ADRs relevant to the area you are working in. If either is absent, continue. The domain-modeling skill creates domain docs as terms and decisions are settled.

Use glossary terms in issue titles, proposals, hypotheses, and test names. Record gaps for domain modeling. If a proposal conflicts with an ADR, identify the ADR and explain why the decision should be revisited.
